# SANS_itmo

# Лабораторная работа II: Обучение языковой модели GPT с поддержкой Packed Batching

## 1. Архитектура модели

В рамках данной лабораторной работы реализована авторегрессионная языковая модель **GPT-подобной архитектуры** (Decoder-only Transformer) на базе PyTorch и PyTorch Lightning. Модель обучается предсказывать следующий токен последовательности на основе всей предыстории (Causal Language Modeling).

### Ключевые компоненты архитектуры:
1. **Token & Positional Embeddings**: Входные токены переводятся в плотные векторы заданной размерности. Используются обучаемые абсолютные позиционные эмбеддинги.
2. **Transformer Decoder Layers**: Сеть состоит из стека идентичных слоев, каждый из которых включает в себя:
   * **Multi-Head Causal Attention**: Механизм многоголового внимания с применением причинно-следственной маски (Causal Mask), предотвращающей подглядывание в «будущие» токены.
   * **Position-wise Feed-Forward Network (FFN)**: Полносвязная сеть, состоящая из двух линейных слоев с функцией активации GELU (или аналогичной) и промежуточным расширением размерности (`d_ff`).
   * **Pre-Layer Normalization & Residual Connections**: Нормализация слоя применяется перед блоками Attention и FFN (Pre-LN архитектура), что обеспечивает стабильность глубоких сетей и предотвращает затухание градиентов при обучении с нуля.
3. **Language Model Head**: Линейный слой, проецирующий выходное скрытое состояние модели обратно в пространство словаря для получения логитов вероятностей токенов.

## 2. Обоснование конфигурации модели

Текущие параметры архитектуры зафиксированы в конфигурационном файле `configs/config.yaml`:

| Параметр | Значение | Обоснование выбора |
| :--- | :--- | :--- |
| **`vocab_size`** | 50257 | Соответствует размеру словаря обученного на предыдущем этапе Byte Pair Encoding (BPE) токенизатора (эквивалентно GPT-2). |
| **`d_model`** | 256 | Скрытая размерность модели. Выбрано компромиссное значение: достаточно глубокое для улавливания синтаксических паттернов, но легковесное для обучения на доступном GPU (NVIDIA T4 в Google Colab). |
| **`n_heads`** | 8 | Количество голов внимания. При `d_model = 256` размерность одной головы составляет `256 / 8 = 32`, что обеспечивает эффективное распределение подпространств признаков без избыточности. |
| **`d_ff`** | 1024 | Внутренняя размерность блока Feed-Forward. По классической традиции архитектуры Transformer устанавливается как $4 \times d_{model}$, что позволяет нелинейно обогатить признаки перед переходом к следующему слою. |
| **`n_layers`** | 6 | Количество декодерных слоев. Глубина в 6 слоев позволяет модели выучить долгосрочные зависимости в тексте, избегая эффекта переобучения на небольшом пилотном датасете (WikiText/Common Crawl). |
| **`dropout`** | 0.1 | Стандартный коэффициент регуляризации для предотвращения кооптации нейронов и переобучения модели на малых батчах. |

## 3. Оптимизация данных: Packed Batching

Для минимизации вычислительных избыточностей при обучении на разнородных текстах применен метод **Packed Batching**:

1. **Конкатенация и нарезка**: Вместо индивидуального паддинга (padding) каждого текста до максимальной длины, все токенизированные документы склеиваются в один непрерывный поток, разделенный специальным токеном `[SEP]` (EOS), и нарезаются на жесткие блоки фиксированной длины `block_size = 512`. Это позволяет полностью утилизировать контекстное окно модели на 100%.
2. **Векторизованный расчет позиций**: Локальные позиции токенов вычисляются динамически на основе вектора `sequence_ids` (индексов исходных документов), сбрасывая счетчик позиций обратно в `0` на стыке документов.
3. **Маскированная функция потерь (`compute_packed_loss`)**: Кросс-энтропийный Loss вычисляется с учетом специальной маски (`loss_mask`), которая зануляет градиенты на стыках документов и на позициях паддинга. Модель штрафуется только за реальные предсказания внутри документов, что предотвращает искажение языковой интуиции на границах склейки текстов.

## 4. Гиперпараметры обучения и стратегия оптимизации

Выбор параметров обучения обусловлен необходимостью стабилизации градиентов в глубоких авторегрессионных сетях:

* **Оптимизатор AdamW**: Используется адаптивный шаг со скорректированным затуханием весов (`weight_decay: 0.01`). Из оптимизации весового затухания исключены смещения (biases) и параметры LayerNorm, что является стандартной практикой для сохранения стабильности обучения.
* **Косинусное затухание скорости обучения (Cosine Annealing LR) с линейным прогревом (Warmup)**:
  * В течение первых `warmup_steps: 500` скорость обучения линейно растет от 0 до базового значения `lr: 3e-4`. Это защищает модель от расхождения градиентов на этапе случайной инициализации весов.
  * После прогрева скорость обучения плавно снижается по косинусной траектории до нуля к моменту `max_steps: 5000`, обеспечивая мягкую сходимость в локальный минимум в конце обучения.
* **Обрезка градиентов (Gradient Clipping)**:
  Значение `gradient_clip_val: 1.0` ограничивает **глобальную L2-норму** градиентов. Это критически важное требование для языковых моделей (предотвращает проблему «взрыва градиентов» при резком изменении динамики лосса).
* **Размер батча (Batch Size)**:
  Значение `batch_size: 32` сбалансировано под физические ограничения видеопамяти графического ускорителя, предотвращая ошибки типа *Out of Memory (OOM)*.

## 5. Мониторинг и воспроизводимость
В процессе обучения с помощью кастомного колбэка `GradNormLoggerCallback` осуществляется непрерывный мониторинг **локальных норм градиентов каждого слоя** и общей глобальной нормы. Все метрики (Loss, Perplexity, Learning Rate, нормы градиентов) логируются в TensorBoard / ClearML. Реализовано автоматическое сохранение лучшего чекпоинта по метрике `val_loss`, а также сохранение состояния `last.ckpt` для бесшовного возобновления сессии обучения при сбое среды выполнения.
